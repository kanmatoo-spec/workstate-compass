# 実行例

以下の会話は期待する動作を説明する架空例です。実モデルで取得した実行ログではありません。
使用するファイル名・ジョブ ID は例示です。

## A. 通常の「続けて」

- 直前の状態: エラー表示の修正が保存済み。次は関連テスト。前の処理の終了コードも確定している。
- ユーザー: 「続けて」
- 期待する動作: 「修正は保存済みなので、関連テストから続けます。」としてテストへ進む。
- 行わないこと: 再開のためだけの全リポジトリ調査、全履歴読み直し、チェックポイント新規作成。

## B. 使用量制限後、ビルドがまだ実行中

- 直前の状態: ビルドセッション `job-example-42` を開始して中断。終了結果は未取得。
- ユーザー: 「制限が解除されたので続けて」
- 期待する動作: そのセッションの状態を確認する。実行中なら同じジョブを追跡する。
- 成功なら: 既存成果物を使い、残っている受け入れ確認へ進む。
- 失敗なら: ログと部分成果物を確認し、必要な修正・安全な再試行だけを行う。
- 行わないこと: セッションが見つからないという理由だけで成功／未実行を断定すること。

## C. PR 作成の応答が失われた

- 直前の状態: 元のユーザー承認範囲内で PR 作成を実行したがタイムアウト。
- ユーザー: 「続行」
- 期待する動作: 同じリポジトリ・head・base の PR を照会し、存在すれば再利用する。
- 照会できない場合: 作成操作だけを保留し、不足情報を短く確認。独立した検証や説明文の整備は続行。
- 行わないこと: 応答がないことを失敗とみなして別の PR を作成すること。

## D. 別セッションで文脈が足りない

- ユーザー: 「このプロジェクトの docs/progress.md から再開して」
- ノート: 入力検証は実装済み・検証済みと記録。
- 実状態: その後、入力検証に影響する依存関係が変更されている。
- 期待する動作: 対象と目的を確認し、実装を保持しつつ影響するチェックを再実行する。
- 行わないこと: 古い「検証済み」をそのまま採用することや、実装を最初から作り直すこと。

## E. 再開対象を特定できない

- ユーザー: 文脈のない新しいチャットで「続けて」。対象プロジェクトも不明。
- 期待する返答: 「再開するプロジェクト、または進捗メモの場所を教えてください。」
- 行わないこと: 最近使った別チャットを選ぶこと、ホーム全体を検索すること。

## 補助ツールを単独で試す

展開した配布物のルートで、次のコマンドは同梱ファイルだけを読みます。

```sh
python skills/workstate-compass/scripts/evidence.py --repo . --path README.md --path skills/workstate-compass/SKILL.md --no-git
```

出力の要点（ハッシュ値とサイズは実ファイルにより変わります）:

```json
{
  "schema_version": 1,
  "scope": ["README.md", "skills/workstate-compass/SKILL.md"],
  "git": {"state": "not_requested"}
}
```

実際の出力には `files` 配列があり、各ファイルの `state: observed`、`size`、`sha256` と
非原子的な部分観測である旨の `notice` が含まれます。この例は省略表示です。
状態が `missing` なら成功扱いせず、指定パスと作業場所を確認します。
