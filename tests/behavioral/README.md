# 実モデル行動評価の再現手順

この評価では、モデルに回答案を選ばせるだけでなく、隔離したファイル・Git・テストを実際に操作させます。
ビルド状態、PR、通知は `lab.py` のローカル模擬サービスです。実際の公開・送信・ネットワーク通信は使いません。

## 準備

Python 3.10+ と Git を用意し、配布物のルートから実行します。新しい保存先だけを指定してください。
`setup_cases.py` は既存の保存先があれば停止します。モデルやAPIの自動呼び出しは行いません。

```sh
python -B tests/behavioral/setup_cases.py --dest .test-work/eval-001
python -B tests/behavioral/grade_cases.py --run .test-work/eval-001 --baseline
```

12個のケース、Skill のコピー、各ケース用の `prompts/*.txt` を生成します。
一部だけ再評価する場合は、別の保存先と `--case mixed_git --case light` などを指定できます。
baseline はモデルを実行する前に一度だけ保存します。上書きはしません。

## モデルを実行

各 `prompts/<case>.txt` を、それぞれ新しいコンテキストの Codex に渡して実行します。
Skill 作成・採点の会話履歴は引き継がず、`grade_cases.py`、評価仕様、期待結果は渡しません。
モデルにはプロンプトに記載したケースだけへのアクセスと、適切な Python の実パスを与えます。
評価用の追加権限を既存プロジェクトに与えず、外部操作はローカル模擬サービスに限定します。

AGENTS.md ケースでは、「project/AGENTS.md を読む」という開始指示を与えます。
これは **読んだ AGENTS.md から適切な Skill を選べるか**の評価です。
製品の自動探索、Skill 一覧への表示、暗黙マッチングの発動率を測るものではありません。

各モデルは実作業の後、`model-report.json` に操作を記録します。
模擬サービスは `actions.jsonl`、実テストは `check-result.json` に結果と入力ハッシュを記録します。
ケースをまたぐ質問への回答や、正解へ誘導する追加指示は与えません。

## 観測と判定

```sh
python -B tests/behavioral/grade_cases.py --run .test-work/eval-001
```

このスクリプトは模擬サービスの操作回数、テスト結果・入力ハッシュ、元ファイルとステージ済み差分の保持を検査します。
その上で、評価者が最終回答、読み取った範囲、Gitコマンドの対象限定、曖昧さへの対処を確認してください。
`observable_checks_passed` だけでモデル行動全体の合格とはしません。
操作回数が違う場合も、目的に合った別の手順か、不必要な再実行かを区別します。

シェルの全コマンドは独立した監査機構で収集していません。`model-report.json` はモデル自身の記録であり、
模擬サービスのログ、実ファイル、検証の入力ハッシュと照合して使います。
プロンプトで指定されていない別のテスト経路を使った場合は、失敗と即断せず、観測不足として追加確認します。

評価を繰り返す際は新しいケースを生成します。完了済みのケースを再利用すると、復旧ではなく完了状態の確認になってしまいます。
公開する記録からは、ユーザー名、個人の絶対パス、認証情報を取り除いてください。
